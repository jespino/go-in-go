A host is any Go program (Go 1.22 or later, with or without cgo) that
imports `github.com/jespino/go-in-go/gig`. Usually it goes through
bindings generated by [`go-in-go bindgen`](/docs/commands/#go-in-go-bindgen).

## Loading

```go
m, err := greeter.Load("greeter.gig", myImports, &gig.Options{
	HeapMax: 256 << 20,
})
if err != nil {
	log.Fatal(err)
}
defer m.Close()
```

`Load` maps the module into memory, resolves its imports against
`myImports` (which implements the bindings' `Imports` interface), checks
every signature, and runs the module's package initializers and `main`.
Use `LoadBytes` to load a module from memory, for example one embedded in
the program:

```go
//go:embed greeter.gig
var greeterModule []byte

m, err := greeter.LoadBytes(greeterModule, myImports, nil)
```

Each `Load` creates an independent **instance**, with its own memory,
globals and goroutines. Loading is cheap (it maps memory and runs `main`),
and you can load the same module many times.

## Options

`gig.Options` (pass `nil` for the defaults):

| Field | Default | Meaning |
|---|---|---|
| `HeapSize` | 4 MiB | initial heap of the module |
| `HeapMax` | 1 GiB | the heap grows up to this. It's reserved as address space when loading, but memory is only used as the heap grows. |
| `StackSize` | 1 MiB | the module's system stack (its scheduler and runtime run there; goroutine stacks are on its heap) |
| `Stdout`, `Stderr` | `os.Stdout`, `os.Stderr` | where the module's output goes: `fmt.Println`, `println`, panic messages |
| `Background` | `false` | keep the module's goroutines running between calls (see below) |
| `Imports` | | set by the generated bindings |

## Calling

Call the exports as methods. Each returns the export's results plus an
`error`:

```go
n, err := m.WordCount(text, 4, 3)
```

Arguments and results are copied. Strings and byte slices you pass can be
reused or changed right after the call; the ones you get back belong to you.

## Errors

A call can fail in these ways, besides errors the export itself returns:

| Error | When | Instance afterwards |
|---|---|---|
| `gig.ErrAborted` | the module panicked, deadlocked or ran out of memory (the message went to `Stderr`) | dead |
| `*gig.FaultError` (`errors.Is(err, gig.ErrFault)`) | the module crashed: segfault, bus error, illegal instruction, stack overflow | dead |
| `gig.ErrClosed` | the instance was closed | closed |
| `gig.ErrReentrant` | a host function called back into the instance that called it | usable |
| an error mentioning a host function | one of your `Imports` methods panicked | dead |

A `FaultError` says where the module crashed:

```
gig: module crashed: segmentation fault at module+0x7e6a (main.Peek+0xa), address 0x18
```

A dead instance returns the same error from every later call, and
`m.GigInstance().Err()` reports it. Your program isn't affected: close the
dead instance and load a new one (a `gig.Pool` does that for you).

## Host functions

Your `Imports` methods are ordinary Go code, running on the goroutine that
made the call into the module. They can do anything, except call back into
the same instance: that returns `gig.ErrReentrant` (calling into *other*
instances is fine). A panic in a host function aborts the call and kills
the instance; your program keeps running.

## Concurrency

An instance runs one call at a time. Calls from several goroutines into
the same instance are serialized: each waits until the instance is free.
While a goroutine is inside a module, your program's scheduler and garbage
collector keep running normally; the module doesn't stop the world.

For parallel calls, use a pool of instances:

```go
p, err := gig.NewPool(runtime.NumCPU(), func() (*greeter.Module, error) {
	return greeter.Load("greeter.gig", myImports, nil)
})
if err != nil {
	log.Fatal(err)
}
defer p.Close()

var s string
err = p.Do(func(m *greeter.Module) error {
	var err error
	s, err = m.Greet("gopher")
	return err
})
```

`Do` runs the function with an idle instance, waiting for one if all are
busy. Instances are independent, so pools suit modules whose exports don't
rely on state kept between calls. An instance that died is replaced the
next time it's picked. `Close` waits for running calls and closes every
instance.

## Background goroutines

By default, a module's goroutines only run while a call is in progress. A
goroutine started by an export (a ticker, a worker) is paused between
calls. With `Background: true`, a goroutine of your program keeps running
them between calls, whenever one is runnable or a sleeping one is due:

```go
m, err := ticker.Load("ticker.gig", myImports, &gig.Options{Background: true})
m.Start(10) // starts a module goroutine that calls an import every 10 ms
// ... the import keeps being called while the host does other things
m.Close()   // stops it
```

Module goroutines are scheduled cooperatively: one that loops without ever
blocking keeps the instance busy, and calls wait for it.

## Heap statistics

```go
st, err := m.GigInstance().HeapStats()
// st.InUse, st.Arena, st.TotalAlloc, st.NumGC
```

`Arena` is the current heap size, which grows up to `HeapMax`. `TotalAlloc`
is the clearest sign of GC activity: TinyGo's `NumGC` doesn't count every
collection.

## Without bindings

The bindings are generated code over a small low-level API, which you can
also use directly, for example to call modules you don't know in advance:

```go
in, err := gig.Load("greeter.gig", &gig.Options{
	Imports: map[string]gig.Import{
		"Log": {Fn: func(c *gig.HostCall) { log.Println(c.String(0)) }},
	},
})

idx, err := in.Export("Greet", "(string)(string,error)") // "" skips the signature check
f, err := in.Begin(idx) // locks the instance until End
defer f.End()
f.SetString(0, "gopher")
if err := f.Run(); err != nil { ... }
s, err := f.RetString(0)
moduleErr, err := f.RetError(2)
```

Values travel as 64-bit **slots**: `string`, `[]byte` and `error` take two
slots, every other type one. `in.Manifest()` lists the exports and imports
with their types. See the [API reference](/api/gig/) for every method.
